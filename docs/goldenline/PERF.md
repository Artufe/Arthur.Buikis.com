# GOLDENLINE — performance

Target: 90 FPS sustained at 2560×1440 on an RTX 5070 Ti (11.1 ms), 60 FPS floor, no frame above
median + 4 ms. Dev proxy: Apple M3 (base), 1280×720, preset `high`, median ≤ 22 ms.
Measure with `node scripts/goldenline-shot.mjs --shot <name> --perf 10 --size 1280x720`.

## Log

- [orchestrator] Base with stubs, `beach-sun` 1280×720 high on M3: median 8.3 ms, 1% low 9.2 ms, 6 draws, 0.30 M tris.
- [pier] `pier-under-water` 1280×720 high, pier.visible on/off alternated 4× in one session (shared GPU, 5 other agents): CPU `systemMs.pier` 0.40–0.71 ms (was 1.9 ms before round-robin ocean sampling); GPU scene pass on 4.4–5.6 ms vs off 3.3–3.5 ms (≈ +1.1 ms; the pier's shadow-cascade share could not be separated because the pre-scene timestamp slots were unstable under the shared GPU). +56 draw calls across passes, ~480 k tris per pass. Spray compute: one 4096-thread dispatch while bursts are alive, 0 otherwise. Frame was vsync-capped at 8.3 ms either way.
- [pier] Allocations (CDP sampling heap profiler, 64 B interval incl. collected objects, 600 stepped frames after a 3000-frame warm-up, surge on so spray fires): ~1.1 KB/frame inside `pier/water-fx.ts` update, all V8 double boxing of `state.splat()` arguments (16 calls/frame); ~0.05 KB/frame in `pier/index.ts`; ~0.03 KB/frame in three's `renderer.compute` internals. No `new`, closures, arrays or strings in any pier update.
- [ocean] GPU timestamp queries of isolated work (`ocean.gpu.benchFFT` / `benchRender`, frozen sim, shared GPU): both FFT passes for 4 cascades 0.10–0.16 ms, + compute mip chain ≈ 0.13–0.21 ms total; ocean mesh alone into a 1280×720 target 0.47 ms (`lineup`) / 1.2 ms (`beach-sun`, no terrain occlusion in the solo render), 0.40 ms at 2560×1440 (vertex-bound). Replacing three's render-pass mip generation (64 passes) with the compute chain saved ≈ 2–6 ms/frame wall. CPU `systemMs.ocean` 0.15–0.3 ms (three's per-dispatch binding updates dominate). `sample()` ≈ 27–33 µs/call (`gpu.sampleCoarse` ≈ half; + ≈ 0.1 ms once per frame on the first call); `wave()` ≈ 1 µs.
- [ocean] Allocations (CDP sampling heap profiler, 64 B interval, 900-frame warm-up then 300 frames with 400 `sample()`/`wave()` calls per frame): 0 bytes attributed to any ocean frame; Node sampling profile of 200 k `sample()`/`wave()` calls: none.
- [atmosphere/post] `beach-sun` 1280×720 high, everything on, quiet machine: median 8.3–8.8 ms (vsync-bound at 120 Hz, so the true frame is lower). `systemMs.render` (CPU to encode the whole frame, all systems + post) 3.0–5.7 ms; with `atmosphere.shadows=0` 3.4 vs 5.7 ms in the same session → the four cascades cost ≈ 2 ms CPU (every caster re-encoded per cascade). A/B bench (scratch `bench.mjs`: 20 back-to-back renders + `onSubmittedWorkDone`, base/variant alternated 5× per toggle in one page) at 720p: TRAA 0.42, SSR 0.33, GTAO 0.28, shadows 1.96 (CPU-bound), clouds/fog/bloom/MB/sharpen within ±0.4 ms noise; at 1440p the deltas were not separable from other agents' GPU load (some negative). GPU timestamp slots on the M3 are inflated by pass overlap (tile-based GPU) + preemption, so per-pass `gpuMs` is not used here; B2 should re-measure on a quiet machine or the 5070 Ti, where the same `gpuMs.{scene,post,preScene}` split is meaningful.
- [atmosphere/post] Allocations (CDP sampling heap profiler, 256 B interval incl. objects collected by minor/major GC, 460–660 free-running frames, `beach-sun`): 0 B attributed to atmosphere/post `update()` code. Remaining attributable: ~146 B/frame inside three's `renderer.render` for the reflection pano (1 quad every 30 frames), and three's own timestamp-query resolve (runs regardless: the pool self-resolves on overflow when `trackTimestamp` is on). The frame overall shows ~200 KB/frame inside three's WebGPURenderer (render-object cache keys, `lightsNode.getCacheKey(true)` forced once per render call, shadow updates) — engine internals, flagged for B2.
- [player] M3, 1280×720 `high`, demo 3 (paddling) / demo 6 (walking), six agents on the GPU. CPU `systemMs.player` 0.38–0.44 ms (was 0.55 before cutting redundant `ocean.sample` calls; ~0.05 ms per sample, 3–4 per frame when prone, 1 when walking on land). GPU: toggling `player.body`+`player.board` changed the scene pass by less than the run-to-run noise (5.3–6.9 ms either way); upper bound ~0.4 ms. Limb LOD: hands 2 mm, feet 2.6 mm, upper arm 4.5 mm, thigh/shorts 6.8 mm (56 k tris per arm, 66 k per leg). Zero allocations in update (by inspection; closures and literals hoisted, all scratch preallocated).
- [beach] Frame-time A/B inside one page (scratch `fps.mjs`: uncapped rAF via `--disable-gpu-vsync --disable-frame-rate-limit`, 1280×720 high, configs toggled live and alternated 5×, min of per-round medians; shared GPU). `beach-sun`: all on 9.9 ms, `beach.terrain=0` 7.3, every beach group off 6.5 → beach ≈ 3.4 ms. `beach-dune`: all on 10.1, `beach.plants=0` 8.5, all off 6.3. The terrain cost barely moves with render scale (0.5× saves 0.3 ms) or LOD density (`beach.lodRange` 2.1 vs 3.5: 9.8 vs 11.2 ms), i.e. it is vertex/submit-bound on the M3 (CPU profile: `createCommandEncoder`/`getCurrentTexture`/`writeBuffer` dominate the frame). Before the perf pass the beach cost ≈ 14 ms (6.9 M seaweed tris, unbranched shader, terrain casting into 4 cascades, 8-tap base heights). Terrain casting shadows (`beach.terrainShadow`) adds ≈ 1.5 ms and is off: at 11° the sand never visibly shades itself.
- [beach] Allocations: CDP sampling heap profiler (256 B interval, 5 s free-running loop with the camera walking along the beach so LOD selection, chunk culling and vegetation updates run every frame): no sample attributed to any beach function (`CdlodSelector.update/select/add/dist/visible`, `ChunkedInstances.update`, `sync`). By inspection: `update()` only writes preallocated typed arrays / uniform values and reuses one update-range object. No pipelines are created after load (instrumented `createShaderModule`/`createRenderPipeline*` over a 12-shot tour: 0).
- [state] GPU cost measured in isolation with timestamp queries (`state.__bench(n, mask)`: n batches submitted synchronously, resolved before yielding, so no frame's passes are included; median of 5; ≈0.17–0.3 ms of contamination subtracted from the "none" baseline). `beach-sun`: far 0.35–0.42, near 0.45–0.5, sand 0.23–0.25, all 0.9–1.0 ms. Stress (`lineup`, 300 foam splats r 3.5 m + 100 moving wakes per frame, 92 % of the near window foamed): near 1.2, all 1.8 ms — texture-fetch bound (13-tap wave stencil + Catmull-Rom in currents). Before the perf pass: 7–13 ms (procedural Voronoi/value noise per texel per frame); the bakes cut it ~4×, the sand schedule another ~1 ms. Next step if needed (B2): a shared-memory stencil for the wake wave equation.
- [state] Allocations (CDP sampling heap profiler, 256 B interval incl. objects collected by minor/major GC): 600 engine frames after a 3600-frame warm-up — 0 B attributed to any state function. `__allocTest(600, 500)` (500 splats queued per frame, full CPU step): ~15 B/frame in binning (sampling noise level, 0.03 B/splat); splat() with Smi arguments: 0. Callers passing doubles to `splat()` can box them at a non-inlined call site (the pier's measurement above) — use `state.reserve()` + `state.splatData` for bulk writers. Found and fixed on the way: `Math.hypot`/`Number.isFinite`/`Math.random` results and doubles stored into three `Vector` fields (tagged in this app: every changing double store allocates) → per-frame doubles now live in a Float32Array uniform block; tunables sync on param change only; three's `updateRanges` re-push after `length = 0` → pinned range objects. three's own `renderer.compute()` allocates ~1 KB per call (timestamp-UID strings with map/join, binding cache keys) — engine internals, flagged for B2.
- [orchestrator] Startup baseline (`--boot`, dev server, M3, shared GPU): engine boot 24.9 s (warmup beach 16.0 s = first synchronous full-frame pipeline compile; warmup pier 3.0 s; compileAsync 2.2 s; init beach 1.1 s; init player 0.9 s) + ~19 s dev route compile. Owner: B2.
